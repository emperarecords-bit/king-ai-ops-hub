# Operational Evidence Log

The friction log for **operating** businesses on the Hub (starting with AccurateBids).
Distinct from `BETA-EVIDENCE.md`, which covered building the platform.

## The discipline

Every friction point is **classified before** anyone proposes engineering. Only one
category is eligible for platform work — and even then, only on **repeated** evidence.

| Class | Meaning | Fix path |
|---|---|---|
| **Process** | Our own workflow/sequence is wrong | Change how we operate |
| **User behavior** | The person didn't do the thing (or did the wrong thing) | Coaching / expectation-setting |
| **Training / docs** | The capability exists but wasn't known or understood | Document / explain |
| **Product (AccurateBids)** | The contractor-facing product has a gap | AccurateBids backlog (separate from the Hub) |
| **Hub platform** | The operating system itself can't do a needed thing | **Only class eligible for Hub engineering** |

**Rule:** a Hub-platform item is not built on first sighting. It must **repeat across
substantially different situations** before it earns the smallest justified change.
One occurrence = logged, not built. (Same threshold that governed EV-009 in beta.)

## Entry format

```
### OE-### — <one-line friction>
- Date / context:
- What happened (observed, not interpreted):
- Class: Process | User behavior | Training/docs | Product(AccurateBids) | Hub platform
- Evidence count: (how many times seen; which distinct situations)
- Recommendation: (operate-differently / coach / document / AccurateBids-backlog / Hub-change-if-repeated)
```
